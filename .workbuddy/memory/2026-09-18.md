### 关键约束（后续改动必须保持）
1. HTTP 是自己手写的极简 HTTP/1.1，不是 NanoHTTPD：避免 gzip 吃掉 SSE、避免每连接一线程。SSE 响应必带 `Cache-Control: no-cache, no-transform` + `X-Accel-Buffering: no`，永不 gzip。
2. 推理线程宿主是 `InferenceLoop`（常驻单线程事件循环，不能用线程池 —— 绑核/nice 按 tid 生效，换线程就失效）。排空钩子注册在它上面。
3. 三层削减：JS 20 字符/30ms 聚合（RN 桥次数）→ native 批量排空（帧数）→ SSE 双阈值 12 字符/60ms（socket 写次数）。
4. 单并发是刻意的：Semaphore(1) + 有界等待位 + 超时，队列满丢弃 token 并计数上报。
5. ModelStore 只改了 `get isAutoReleaseEnabled()` 一处（读 `residencyGuard.shouldKeepModelResident()`），不碰 `useAutoRelease`、不改调用点签名 —— 服务关掉后行为必须逐字回到原样。residencyGuard 是单向小模块，用来打断 ModelStore ↔ LocalApiStore 的循环依赖。
6. 所有调优调用必须 catch `Throwable`（UnsatisfiedLinkError 是 Error）；报告展示「请求值 / 实际回读值 / 拒绝原因」，绝不因为没抛异常就显示「已生效」。

### 第二轮审计补的洞（用户要求逐条核对后）
1. 64KB 管道之前只是个没被使用的参数 → 真正实现：`RequestContext.enqueueFrame(bytes, budget)` 按字节预算入队，溢出丢弃并计数（`pipeDroppedFrames` / `pipePendingBytes` 进 status 与 /health）；终止帧与 [DONE] 不受预算限制。
2. `drainWindowMs`（40ms）之前没生效 → `RequestPipeline.drain()` 按窗口节流，延迟预算回到「JS 30ms + 排空 40ms ≈ 70ms」。
3. CORS 预检被 401：浏览器 preflight 不带 Authorization → `handle()` 里 OPTIONS 必须先于鉴权。
4. 停机顺序：`stop()` 先关在途 socket（维护 openSockets 集合）再收线程池，否则 SSE 会截断在半帧。
5. 前台服务（原文的可选项）已实现：`LocalApiForegroundService` + `FOREGROUND_SERVICE` 权限 + manifest service 声明，start/stop 挂在服务启停上。
6. 新架构事件订阅不能依赖 `NativeModules.LocalApiServer`（TurboModule 惰性创建）→ 拿不到就用 `new NativeEventEmitter()` 订阅 RCTDeviceEventEmitter。
7. 能力边界常驻报告：`BOUNDARY_NOTES`（哪些有效/哪些需 root）每次 apply 都放进 notes，而不是只在失败时说。
8. 报告新增「目标核（设备实际解析）+ 生效核数」，与「强制核数（用户意图）」分开显示。

### 本机编译尝试（结论：这台机器编不出 APK，原因与证据）
- 已跑通的部分：`yarn install`（766 包，`.yarn-integrity`）、`patch-package`（2 个补丁）、
  Gradle 9.0.0 + JDK 17、`generateCodegenSchemaFromJavaScript` / `generateCodegenArtifactsFromSchema`
  （说明新增的两个 TurboModule spec 能过 codegen）、NDK 27.3.13750724（本机原本是空目录，
  已用 `sdkmanager` 补装 2.25GB 到 `D:\Android\sdk`）。
- 卡点 1（硬阻塞）：`LongPathsEnabled=0`（无管理员权限，注册表写入被拒），CMake 对象路径 376 字符
  → ninja 直接 `Filename longer than 260 characters`。改根目录/子目录名最多省 ~35 字符，不够。
- 卡点 2：3.9GB 内存，Metro 打包 node 堆 1986MB → `JavaScript heap out of memory`；
  解法是 `NODE_OPTIONS=--max-old-space-size=3200`（下次构建必须带）。
- 卡点 3：后台任务反复被外部终止；`Start-Process cmd` 被安全策略拒绝。可行姿势：
  **前台 PowerShell 调用 + 10 分钟超时自动转后台**，且长任务要 `dangerouslyDisableSandbox`。
- 交付：`D:\PocketPal-LocalApi-服务与调优-源码.zip`（1565 文件 / 20.1MB，排除 node_modules 与所有 build 产物）
  + 工程内 `ANDROID_BUILD_CN.md`（含可照抄的构建命令与真机验收步骤）。
- 两个本机新增的环境改动（未写进 zip）：`D:\jdk17`（Temurin 17.0.2）、`D:\Android\sdk\ndk\27.3.13750724`。

### 迁移用打包（用户要拿到另一台机器编译）
- `D:\PocketPal-完整工程-含node_modules.zip`：**全量**打包整个工程（76,142 文件 / 436.4 MB /
  源目录 1622 MB），含 node_modules（1585 MB）→ 另一台 Windows 机器可跳过 1 小时的 yarn install。
  已过全量 CRC 校验（`zipfile.testzip()` → None）。打包耗时 12m35s（deflate level 6）。
- `D:\PocketPal-LocalApi-服务与调优-源码.zip`：精简版 20.1 MB（不含 node_modules / build 产物），

  ② 装 NDK 27.3.13750724（否则 `[CXX1101] ... did not have a source.properties file`）；
  ③ 构建时带 `NODE_OPTIONS=--max-old-space-size=3200`，否则 Metro 打包 OOM。
- node_modules 是本机 Windows x64 状态（已跑过 patch-package），跨平台（如 macOS）不能复用，需重新 yarn install。

### 环境注意
- 本机没有 node_modules（zip 里也不含），构建前必须 `yarn install`。
- `npm.ps1` 被执行策略禁止，调用 npm 必须写全路径 `'C:\Program Files\nodejs\npm.cmd'`。
- `package.json` 用 yarn.lock：`npm install` 会因 react-native-windows 的 peer 冲突 ERESOLVE 失败，必须用 yarn。
- 工程里 `google-services.json` 是**占位文件**（原本缺失），发布前应换成真实配置或接受 Firebase 可选功能失效。
